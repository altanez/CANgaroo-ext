# Задача для агента: поддержка команды 'G' (возврат устройства в режим GATEWAY) в SLCAN-драйвере

## Контекст

Прошивка платы WeActStudio STM32G474CEU6 (скетч `WeActStudio_G474CE_Template`,
репозиторий `d:\!acer\!NW\WeAct474`) поддерживает два режима работы:

- **GATEWAY** — штатный режим шлюза. **Активен по умолчанию после reset.**
  В этом режиме устройство НЕ говорит протоколом SLCAN; COM-порт слушает
  только одну команду: `S` + Enter (`\r`) — переход в режим SLCAN
  (в ответ устройство шлёт строку `SLCAN mode\r`).
- **SLCAN** — полноценный SLCAN-сканер (LAWICEL ASCII + FD-расширения
  CANable 2.0), совместимый с этим форком cangaroo. USB VID/PID
  устройства — `16D0:117E` (CANable 2.0), определяется автоматически.

В режиме SLCAN прошивка дополнительно к стандартному протоколу принимает
команду-расширение:

### Команда `G` (возврат в режим GATEWAY)

- Формат: один байт `G` + терминатор CR (`\r`), т.е. строка `"G\r"`.
- Принимается **в любой момент** (канал открыт или закрыт — неважно;
  если канал открыт, прошивка закрывает его сама).
- Ответ устройства: CR (`0x0D`) = ACK, как за обычную команду.
- После ACK устройство переключается в режим GATEWAY и **перестаёт
  говорить SLCAN**: последующие SLCAN-команды будут молча игнорироваться
  (в GATEWAY-режиме парсится только строка `S\r`).
- Вернуть устройство в SLCAN-режим можно только командой `S\r` (её может
  отправить любой терминал; устройство ответит `SLCAN mode\r`) либо
  сбросом/переподключением питания (после reset — всегда GATEWAY).

### Почему нет конфликта с протоколом SLCAN

Буква `G` (верхний регистр) не используется в LAWICEL/CANable: команды —
`O C S Y M A V E F W Q`, кадры — `t T r R d D b B`, hex-данные — только
`0-9 A-F`. Строчная `g` в этой прошивке занята диагностической командой
(дамп GPIO) — не путать. Команда `S` как переключатель режима существует
только в GATEWAY-режиме, где SLCAN-парсер не активен; в SLCAN-режиме
`S` — это всегда двухсимвольная команда битрейта `S0`..`SD`.

## Что нужно добавить в форк

Дать пользователю возможность отправить устройству `G\r`, чтобы вернуть
его из режима SLCAN в штатный режим шлюза (GATEWAY), не переподключая
плату физически.

Релевантный код: `src/driver/SLCANDriver/`:

- `SLCANInterface.cpp` / `SLCANInterface.h` — вся работа с портом.
  Команды хоста отправляются через `writePort()` (см. `SLCANInterface.cpp`,
  функции `writePort(const char*)` / `writePort(const QByteArray&)`,
  ~строки 203–211). Примеры посылки команд: `"C\r"` при закрытии канала
  (~строка 355), `"V\r"`, `"S6\r"`, `"M0\r"`, `"O\r"` (~строки 292–324).
- `SlcanFrameCodec.h` — кодек кадров (трогать не нужно).
- Общий UI настройки интерфейса: `src/driver/GenericCanSetupPage.*`.

Минимальный вариант реализации (на усмотрение агента, можно расширить):

1. При остановке измерения (там же, где сейчас шлётся `writePort("C\r")`)
   **опционально** отправлять `writePort("G\r")` после закрытия канала —
   например, под галочкой в настройках SLCAN-интерфейса
   («Return device to gateway mode on stop», по умолчанию выкл.).
   Обработка ответа не нужна: ACK (CR) сольётся с обычным потоком
   подтверждений; после `G` устройство замолкает — это нормально,
   не считать ошибкой/таймаутом.
2. Кнопка/пункт меню «Send 'G' (gateway mode)» в setup-странице
   SLCAN-интерфейса — посылает `G\r` при закрытом канале.

Требования к реализации:

- Слать именно `"G\r"` (без LF).
- Не слать `G` в середине сеанса измерения — прошивка выполнит команду
  в любой момент и SLCAN-сеанс на этом фактически завершится.
- После отправки `G` драйвер может сразу считать устройство «ушедшим»:
  дальнейшие `V`/`E`/кадры отвечать не будут. Не показывать пользователю
  ложных ошибок оборудования в этом случае.

## Проверка

1. Плата с прошивкой `WeActStudio_G474CE_Template`, после reset — в
   GATEWAY. Терминалом отправить `S` + Enter → ответ `SLCAN mode`.
2. Запустить cangaroo → Measurement → Start (устройство видно как
   CANable 2.0) → кадры идут.
3. Остановить измерение с включённой новой опцией (или нажать новую
   кнопку) → устройство должно вернуться в GATEWAY: SLCAN-команды
   (`V\r`) больше не отвечают, на `S\r` устройство отвечает
   `SLCAN mode` (режимы циклируются).
4. Убедиться, что без новой опции поведение драйвера не изменилось
   (обратная совместимость с обычными CANable/SLCAN-устройствами,
   которые на `G\r` ответят BEL — это безопасно).
